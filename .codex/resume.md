# 暂停 重启与压缩恢复

## 恢复顺序

1. 阅读根 AGENTS.md 和 .codex/README.md。
2. 阅读 Doc/项目管理/需求与验收.md、接口契约.md、进度与交接.md，以及 Doc/控制协议/协议实现约定.md。
3. 检查 `git status --short`、`git log -5 --oneline`、`git log --oneline origin/main..HEAD`；远程有可能变化时查询远程，不强推或覆盖历史。
4. 检查对应模块的验证记录与构建日志。读取未提交文件后继续，确认是否存在重启导致的截断或空内容。
5. 检查子代理和实际构建进程。旧任务可以恢复时继续旧任务；已结束进程的 session ID 不能作为运行证据。
6. 只重跑中断或受改动影响的检查。确认模块写入范围，恢复并行工作。
7. 更新进度与交接，写清恢复依据、未完成部分和下一步。

## 暂停时应记录

- 当前分支、最后已推送提交、未提交文件和所属任务。
- 已通过、失败和未运行的验证，不使用模糊的“基本完成”。
- 仍运行的构建命令、进程和日志路径，以及是否允许继续运行。
- 尚需用户输入的事项、上板条件和下一步最小可执行动作。

## 固定注意事项

- 不访问 SL2_100*、sl2_100*、_archive、.history。
- Xilinx 固定使用 D:/tools/Xilinx/Vivado/2022.1 和 D:/tools/Xilinx/Vitis/2022.1。
- 构建输出放 PL/build、vitis/build、PC/build 或 artifacts，不能把产物当作源文件提交。
- 未连接实际板卡且未完成 72 小时测试时，不报告硬件连续无丢失验收通过。
