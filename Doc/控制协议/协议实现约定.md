# DAQ 网络协议实现约定

版本 v1.1，2026/09/26，已审核冻结。补充原 Word 文档，网络参数、外框和小端字节序保持不变；用户已授权启动后主动推送及接收停止/状态命令。本版本与同版 Word 作为 PL、PS、PC 的共同实现基线；后续语义变更须协调者审核并同步版本。

## 固定外框与连接

板端 TCP server：192.168.1.10:7，掩码 255.255.255.0，网关 192.168.1.1。仅一个控制/数据客户端。

`uint32 Hard=0xA5A5A5A5 | uint32 Type | uint32 DataSize | byte Data[DataSize] | uint32 Tail=0xB5B5B5B5`

全部整数显式小端编码，不直接发送编译器结构体。外框固定开销 16 字节。TCP 是字节流，必须处理逐字节拆包、跨 pbuf 链和多帧粘包。单个数据帧总长 32824 字节，其中 DataSize=32808（40+4096×8）。采样频率固定 1000000 Hz、每样本 8 字节，正常会话不降采样、不暂停采样节拍。

板端接收请求的 DataSize 上限为 16，PC 接收板端帧的 DataSize 上限为 32808。先验证长度再读取载荷；不能按未经检查的长度申请内存。错误包头、超长载荷、错误包尾或接收半帧超过 5 秒时，报告本地协议错误并关闭连接，不在坏流中猜测恢复帧边界。长度在上限内且外框合法但命令/字段非法时，沿用请求 Type 返回 BAD_REQUEST，继续连接且不改变采集状态。未知 Type 也沿用该 Type 返回 BAD_REQUEST；PC 将未请求且非合法推送类型的帧视为协议错误。

第二个 TCP 客户端在已有连接时直接关闭，不影响第一个连接。空闲的合法连接可以长期保持；PC 采集中每秒查询一次状态。PC 可选择连接目标，但不能通过协议修改板端固定 IP、掩码、网关或端口。

|Type|用途|请求 Data|
|---|---|---|
|0xC00000FF|复位会话，仅 IDLE 或资源清理完成的 FAULT 允许|空|
|0xC00100FF|开始|四个 uint32：mode、sample_hz、block_samples、reserved；mode 1=上传/2=SD/3=双输出，其余固定 1000000/4096/0|
|0xC00200FF|停止并排空|空；最终应答在所有尾块处理完后发出|
|0xC00300FF|查询状态|空|
|0xF00000FF|板端数据推送|下述数据块|
|0xC00400FF|板端异常通知|与状态应答相同格式，result 为错误码|

命令应答沿用请求 Type，Data 固定为下述 64 字节状态结构。模式在开始请求中配置，仅对新会话生效；运行中禁止更改模式。sample_hz、block_samples、reserved 必须等于 1000000、4096、0，否则 BAD_REQUEST。空载荷命令的 DataSize 必须为 0。

除 STOP 等待期间允许一个 STATUS 请求外，PC 同时最多一个未完成命令；同 Type 不得并发或在超时后原连接内重试。STOP 与 STATUS 各有一个独立待答标记，按 Type 关联，二者应答可以任意先后。数据和异常帧是主动推送，不占命令待答标记。板端等待 STOP 完成时再次收到 STOP，返回 BUSY，不重复执行停止；先前 STOP 的最终应答仍须发送。合法 PC 不得发送这种同 Type 并发请求，以免缺少请求 ID 时无法关联。其他不合法并发控制命令也返回 BUSY。

所有板端帧使用同一个有序发送器。一个外框从 Hard 到 Tail 必须发送完，才能发送另一个帧，禁止在数据帧内部插入状态或错误应答。START 成功应答完整进入 TCP 发送队列后才允许首个数据帧；最终 STOP 应答必须排在本会话最后数据帧之后。TCP 重传由 TCP 层处理，应用层不重复发送已入队帧、不实现断线续传。

START、RESET、STATUS 的 PC 应答超时为 5 秒，STOP 为 30 秒（包括排空）。超时后 PC 明确标记本次操作结果未知、当前会话不完整，并关闭连接；不能在同一连接直接重试。设备硬件等待必须有有限超时并报告错误。网络断开后板端撤销 RUN、停止采集并清理旧会话，不能在新连接上补发旧帧；新连接可查询状态，清理中 START 返回 BUSY。

## 会话与状态转换

state 表示应用层状态，与 PL 寄存器位不同。IDLE 表示本次会话已经结束且全部资源已释放；RUNNING 表示正在采样；DRAINING 表示已经请求停止、正在处理尾块或清理；FAULT 表示异常会话的清理已经完成。发现致命故障但还没有清理完时必须使用 DRAINING，不能提前发布 FAULT 终态。

|当前状态|START|STOP|RESET|STATUS|
|---|---|---|---|---|
|IDLE|校验并启动新会话|不新增数据，返回保留的会话结果|清除本次结果和计数|返回当前快照|
|RUNNING|BUSY|撤销 RUN，进入 DRAINING|BUSY|返回当前快照|
|DRAINING|BUSY|如尚无待答 STOP，登记并等待清理完成；已有则不重复登记|BUSY|返回当前快照|
|FAULT|返回锁存故障，要求先 RESET|返回最终故障及计数|执行清理确认并回到 IDLE|返回最终故障快照|

开始仅在无未清致命故障、PL 不采样、PL/PS/DMA 旧资源均排空的 IDLE 状态受理。先检查输出资源及参数，再 CLEAR 并确认 PL 计数归零、准备 DMA 描述符，最后 RUN=1。确认硬件运行后发送 START 成功应答。启动失败必须撤销 RUN 并清理；不得发送成功应答或数据帧。

session_id 是设备本次启动期间递增的 uint64，0 表示没有有效会话。每次真正启动的尝试预留新的非零 ID，失败尝试允许消耗 ID，成功会话的 ID 不重用；参数错误/BUSY 不分配 ID。RESET 将状态快照的 session_id 和会话计数清零，但不能回退 ID 分配器。正常结束保留上次会话快照，直至下一次有效开始或 RESET。设备重启后 ID 可重新从 1 开始，因此 PC 文件和日志必须联合本地连接标识区分会话。

每个新会话的 block_sequence、first_sample_index 和所有采集计数从 0 开始。系统复位命令只复位采集会话及相关外设，不重启 PS、不修改网络配置。RUNNING/DRAINING 中的意外硬件复位属于会话故障，不能继续沿用原 session_id 发送正常数据。

## 停止与异常完成条件

正常 STOP 在 PL 当前采样块边界生效，最大额外采样时间为 4.096 ms；若尚未产生新块首样本则可立即停采。正常结束不存在短块，不补零、不截断，也不将暂停采样作为背压处理方式。

STOP 完成必须同时满足：PL 停采且缓冲排空；最后一个完整 DMA 块已经完成、回收并检查长度和 TLAST；全部完整数据块已完成处理占位接口；上传路径的完整帧均已复制进 TCP 发送队列；未失败的存储路径已完成文件同步和关闭；DMA 和数据槽不再属于旧会话。之后才能发送最终 STOP 应答。

无故障时返回 result=OK、state=IDLE。SD 曾失败但网络正常结束时返回相应 SD 错误、state=IDLE，表示“已停止但存储不完整”；PC 必须结束接收会话并显示该错误，不能继续等待，也不能标作全部输出成功。致命故障结束后返回相应故障、state=FAULT。此处 TCP 入队不能证明 PC 已收到或持久化，PC 需独立比对最终计数。

致命故障包括 PL_OVERFLOW、DMA_ERROR、BUFFER_FULL、NETWORK_ERROR、INTERNAL_ERROR，以及只存储模式的 SD_FULL/SD_IO_ERROR。检测后撤销 RUN，锁存首个致命原因，进入 DRAINING；通道仍可用时发一次 DRAINING 异常通知。允许按顺序处理故障前已验证的完整块，损坏、长度不符或不完整的 DMA 尾块绝不能包装为有效帧。清理完成后，在最后一个可发送数据帧之后发一次 FAULT 终态通知；若已有待答 STOP，再发送相应失败 STOP 应答。没有收到 STOP 请求时不得伪造 STOP 应答。

若 TCP 已断开，或者发送/硬件无法在有限期限内排空，板端关闭连接并清理，PC 以断开标记会话不完整；不保证在坏连接上送达错误通知。FAULT 终态后本会话不再产生任何数据帧。PC 收到 FAULT 即终止本次会话并保留错误和已验证前缀，之后可 RESET 再启动新会话。

## 数据块 Data（40 字节元数据 + 样本）

|偏移|类型|含义|
|---|---|---|
|0|uint32|protocol_version=1|
|4|uint32|flags=0，保留|
|8|uint64|session_id；设备本次启动期间递增，PC 用连接实例和 session_id 联合标识|
|16|uint64|block_sequence，从 0 起连续|
|24|uint64|first_sample_index，从 0 起，每块增加 4096|
|32|uint32|sample_count=4096|
|36|uint32|CRC-32/ISO-HDLC，仅覆盖后续原始样本字节；多项式反射值 0xEDB88320，初值/最终异或 0xFFFFFFFF，check("123456789")=0xCBF43926|
|40|uint64[]|4096 个小端原始样本；目前 data_gen 每样本递增 1|

数据推送的 DataSize 必须恰为 32808，protocol_version=1、flags=0、sample_count=4096，session_id 必须与成功 START 应答一致且非零。PC 拒绝不支持的版本/保留位、错误长度、CRC 或不连续的序号/索引，标记完整性失败并断开；不能忽略坏帧后仍报告完整会话。CRC 按线上小端样本原始字节计算，不含外框和 40 字节元数据，CRC 字段自身按 uint32 小端发送。

## 状态与应答 Data（固定 64 字节）

|偏移|类型|字段及含义|
|---|---|---|
|0|uint32|result，命令结果或锁存会话错误，见下文|
|4|uint32|state，应用层状态|
|8|uint64|session_id，当前或最近结束会话|
|16|uint64|produced_samples，PL 成功产生样本数；未写入的溢出采样不计入|
|24|uint64|uploaded_blocks，完整帧已经复制进入 TCP 发送队列的块数|
|32|uint64|stored_blocks，包含于最近一次成功文件同步中的完整帧数|
|40|uint64|overflow_count，本会话 PL 溢出事件数，PS 对硬件锁存从 0 到 1 计一次，本版本只能为 0 或 1|
|48|uint32|mode，0 无会话、1 上传、2 SD、3 双输出|
|52|uint32|sd_state，存储路径状态|
|56|uint32|queue_used，已由 DMA 完成并被软件回收但尚未归还硬件的数据槽数，包含消费者持有槽|
|60|uint32|queue_capacity，DMA 数据槽总数；不包含 TCP 自有复制缓冲|

- result：0 OK，1 BAD_REQUEST，2 BUSY，3 DMA_ERROR，4 PL_OVERFLOW，5 SD_FULL，6 SD_IO_ERROR，7 NETWORK_ERROR，8 BUFFER_FULL，9 INTERNAL_ERROR。
- state：0 IDLE，1 RUNNING，2 DRAINING，3 FAULT。
- sd_state：0 DISABLED，1 WRITING，2 FULL，3 ERROR，4 CLOSED。
- 上电和 RESET 后 mode=0、sd_state=DISABLED、queue_used=0；queue_capacity 是配置的数据槽容量，在空闲时也可保持非零。正常存储开始后为 WRITING，成功同步关闭后为 CLOSED；存储失败后保留 FULL/ERROR，不因关闭句柄改为 CLOSED。只上传会话始终 DISABLED。
- PC 对命令应答/异常通知要求 DataSize=64，并检查 result/state/mode/sd_state 枚举范围及 queue_used≤queue_capacity。数据推送和异常通知均不要求 PC 发送应用层应答，可靠交付由 TCP 负责。
- START/RESET 应答的 result 表示该命令的执行结果；STOP 表示最终会话结果，STATUS/异常事件表示当前锁存会话错误。BAD_REQUEST/BUSY 不覆盖会话故障锁存。首个致命错误优先于先前 SD 路径降级；没有致命错误时保留首次 SD 错误。sd_state 独立保留 SD 的实际终态。
- 运行中计数并非跨字段原子快照，produced_samples 可领先 DMA/TCP/SD。读 PL 64 bit 计数使用高低高法，最多重试 3 次；无法得到一致值则报告 INTERNAL_ERROR。队列值只表示软件持有槽，不能据此证明没有硬件完成但尚未回收的块。
- 正常 STOP 无丢失验收必须满足：produced_samples 为 4096 的整数倍；上传模式 uploaded_blocks×4096=produced_samples，且 PC 已验证块数等于 uploaded_blocks；SD 正常模式 stored_blocks×4096=produced_samples。PC还须检查每帧 CRC、会话、序号、首样本索引和目前发生器的逐样本递增值。
- 故障终态允许各计数不一致，但必须报告故障并保留这些计数，不能把已收到前缀视为完整会话。PC 发现正常终态计数不一致即判定完整性失败，不显示“尾帧确认成功”。

## SD 存储行为

64 GB 卡在开始前必须挂载已支持的 FAT32 或 exFAT 文件系统；PS BSP 明确启用 exFAT 并验证。程序不自动格式化、不覆盖已有文件。存储相关启动失败返回 SD_IO_ERROR（无卡、不可挂载、只读等）或 SD_FULL，不悄悄将请求模式改为只上传。

SD_FULL 指无法容纳下一完整数据帧及文件系统所需元数据；不能只把“空闲簇恰好为零”当作唯一判据。完整帧写入、同步、关闭的结果必须检查，不能把短写当成功。只有最近一次 f_sync 成功覆盖的完整帧才计入 stored_blocks；建议按 64 帧批量同步，正常结束再同步并关闭，运行中 stored_blocks 因此可以落后于已写帧。

|模式|卡满 SD_FULL|写入或同步错误 SD_IO_ERROR|
|---|---|---|
|只上传|不使用 SD，sd_state=DISABLED|不使用 SD|
|只存储|停止采集，清理后 FAULT；sd_state=FULL|停止采集，清理后 FAULT；sd_state=ERROR|
|存储且上传|立即停写 SD，保持 RUNNING 和上传；发一次异常通知，sd_state=FULL|立即停写 SD，保持 RUNNING 和上传；发一次异常通知，sd_state=ERROR|

SD 路径失败后，不再接收新块写入，也不自动恢复或覆盖旧文件；可以尝试同步/关闭当前文件以保留完整前缀。若清理也失败，记录 SD_IO_ERROR 细节，不能虚增 stored_blocks。一个 SD 降级事件只主动通知一次，后续 STATUS 持续体现锁存结果。双输出随后 STOP 应答遵守“已停止但 SD 不完整”的规则。

只存储模式无需上传原始数据，但控制 TCP 连接仍用于开始、停止、状态和错误报告；失去控制连接也结束采集。本版不提供脱机自动启动或断网继续存储。

## 文件与显示

PC/SD 文件使用 `.daq` 扩展名，按接收/产生顺序存储上述完整数据帧（包含 Hard 到 Tail 的 16 字节外框，无额外私有文件头），可脱机解析复验；每卷不超过 1 GiB，边界在完整帧之间，命令和状态帧不存入数据文件。目录/文件名包含连接或启动标识、会话和分卷编号，禁止覆盖旧文件。采用独占新建语义，名称冲突时选择新的目录或分卷编号；无法创建则报告保存失败，不打开旧文件截断或追加到旧会话。具体文件名格式不属于线上协议，可以分别适配 SD 与 PC 文件系统。

PC 可关闭文件保存，仍需全量接收和校验。磁盘满、短写或刷新失败后停止本地保存、记录路径和最后确认保存位置，继续接收校验和显示；UI 明确“接收正常但保存失败”。不得以网络块计数代替文件保存成功计数。磁盘损坏时尾文件可能有不完整帧，离线复验只能承认校验通过的完整前缀；禁止静默丢弃错误记录。正常关闭文件也必须检查刷新结果。

波形使用完整校验后的有限窗口进行显示抽取，不改变文件内容；显示与接收处理不得共用会阻塞采集的 UI 操作。默认原始值按 uint64 展示，绘图转换 double 仅用于显示。后续真实采样通道格式另行定义，不能自动套用目前的递增发生器校验。

## 冻结后的最低验收用例

1. 外框网络参数保持原值；START/STOP/STATUS/RESET 逐字节拆分、粘连和跨 pbuf 链，字段与小端字节序一致。
2. 超长长度、错误帧头/尾、超时半帧必须断连；合法外框的错误参数/未知类型返回 BAD_REQUEST，不误启动。
3. START 应答先于首帧；STOP 等待期间 STATUS 可独立应答；所有帧不可交叉插入。
4. 停止发生在首样本前、块中、块边界和 TCP/SD 背压时；确认最终尾块、计数等式、资源释放及第二会话从 0 开始。
5. 只存 SD 满、双输出 SD 满、SD 写入/同步失败，分别检查状态转移、一次性异常、最终故障通知/STOP 应答及保留文件。
6. PL/DMA/缓冲故障只发送已验证完整前缀；FAULT 后无旧数据；RESET 后新会话不重用旧 ID。
7. PC 注入 CRC 错、缺块、重复块、乱序、会话错误、最终计数不匹配、保存失败、意外断线，必须可见且不可报告完整成功。
8. 64 bit 计数跨 2^32 边界，1 GiB 分卷跨界后复验连续；真实板卡正常连接持续至少 72 小时，记录首尾样本、总块数、CRC/连续性错误数、吞吐及队列峰值。短时模拟不能代替 72 小时板验。
