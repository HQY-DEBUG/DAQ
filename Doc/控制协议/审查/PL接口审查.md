# PL 接口协议审查

日期：2026/09/26。范围：仅审查现有 PL 接口与跨模块协议；未修改 PL 源码、共享契约或网络协议，未重新仿真或构建。下列第 1–5 项保留为 v1.0 的原始审查记录；文末记录 v1.1 复核结果。

## 审查依据与现状

- 依据 `Doc/项目管理/需求与验收.md`、`Doc/项目管理/接口契约.md`、`Doc/控制协议/协议实现约定.md`，对照 `PL/source/verilog/daq_core/daq_data_gen.v`、`daq_core.v`、`PL/daq.tcl` 和 `PL/验证记录.md`。
- 现有数据源在 100 MHz 时钟下每 100 周期产生一个 64 bit 样本；`sink_available` 不足时锁存溢出并停止，不拉长采样周期。`daq_core` 用两块 4096×64 缓冲，通过 TLAST 握手释放块。现有 Icarus 仿真曾通过；本次仅静态审查。
- 现有 `PL/build/daq/daq_bd_only.xsa` 生成于独立 `daq_data_gen.v` 接入前，且不含 bit，不能证明当前 RTL 或最终硬件。协议冻结后仍需按阶段完成 PL 仿真、BD、综合实现、时序与最终 XSA；当前不启动这些工作。

## 冻结前必须明确的跨模块行为

### 1. RUN 与开始命令的状态门槛

**现状及风险：** `daq_core.v:97,138-150` 允许在尚有待输出块时写入 `RUN=1`，写响应仍可能为 OK；`generator_run` 此时受 `pending` 阻止，一旦 PL 排空便自动开始。这会使排空期间的开始命令成为延后生效的隐式重启。溢出锁存后写 `RUN=1` 也可能短暂得到 OK，但数据源不会启动。协议当前未明确开始命令在 DRAINING、FAULT、未 CLEAR 的 IDLE 状态下的结果。

**建议定稿：** 网络开始命令仅在 PL 停止、PL/SG DMA/PS 队列均排空且无未清故障的 IDLE 状态受理；其余返回 BUSY 或对应故障码，不写 RUN，不分配新 `session_id`。受理后按“清理并确认计数归零 → 先备好 DMA 描述符与输出资源 → RUN=1 → 确认实际采样运行 → 开始成功应答 → 首个数据帧”的顺序执行；若启动失败，返回失败应答并标记会话不可用。PL 实现后续应拒绝非法 RUN 或由 PS 严格阻断，不能依赖延后启动行为。

### 2. 正常停止、故障停止与尾数据的边界

**现状及风险：** `daq_data_gen.v:45,58-59` 在收到停止请求后继续到当前 4096 样本块结束；若正处块边界则直接停采。正常停止没有短块，最多等待一个 4.096 ms 采样块。`daq_core.v:94,203-209` 的 `pending=0` 只表示 PL 缓冲及 AXIS 输出排空，不表示 DMA 已完成、PS 已处理、TCP 已入队或 SD 已写完。现有停止应答条款尚未把这些层次逐一定义。

**建议定稿：** 定义正常停止成功的必要条件为：PL 不再采样、PL 待输出为空、DMA 所有完整块已回收并验证、所选输出路径已完成协议承诺的处理，随后发送最终停止成功应答；应答位于该会话最后数据帧之后。正常停止仅输出 `sample_count=4096` 的完整帧，`produced_samples` 应是 4096 的整数倍。故障停止若存在 DMA 半块或无法验证的尾数据，不得伪造完整帧；定义可保留哪些已验证完整块、故障通知与失败停止应答的顺序，以及何时释放资源。等待停止期间重复停止、查询状态、断连与超时的处理也应固定。

### 3. PL 溢出的损失边界与故障语义

**现状及风险：** `daq_data_gen.v:50-57` 在下一个采样时刻无可写块时置位 `overflow`、停止采样，该未写入样本不计入 `produced_samples`；`daq_core.v:150,166` 将 RUN 请求清零并保留溢出位。当前缓冲结构使正常容量耗尽通常发生在块边界，已有完整块仍可向 DMA 排空。PL 只有溢出锁存位，没有硬件溢出次数寄存器；网络状态却要求 `overflow_count`。

**建议定稿：** 一旦出现溢出，本会话立即进入 FAULT，至少上报一次 PL_OVERFLOW；不得以完整正常停止或连续会话的状态结案。明确 `produced_samples` 只数成功产生的样本，失败的采样事件不计入；`overflow_count` 由 PS 对锁存事件计数，约定是“本会话溢出事件数”还是跨会话累计，不能由单个锁存位推断任意次数。允许继续输出故障前已验证的完整块时，异常通知、尾块、最终失败应答必须有确定顺序；任何部分 DMA 块都不能发送为有效数据帧。下一会话前必须排空并 CLEAR。

### 4. CLEAR、复位与会话重新初始化

**现状及风险：** `daq_core.v:95-96,138-145` 仅在停止且 PL 无待输出时接受 `CONTROL.CLEAR`，否则返回 SLVERR；CLEAR 同时把 RUN 请求置零。`daq_data_gen.v:36-42` 清除相位、样本计数及溢出。硬件 `aresetn` 则可随时清空 PL 状态和块所有权，正在传输的会话可能失去尾数据。网络“复位会话，仅空闲允许”与 PL CLEAR、PS/DMA 复位之间的关系未写清。

**建议定稿：** 规定网络复位会话的前置条件、是否执行 PL CLEAR/DMA 重置、应答时计数和 `session_id` 的值；明确每次成功开始前必须完成 CLEAR，并校验 `SAMPLES_LO/HI=0`、溢出位清零、无待输出。`CONTROL` 同时置 RUN 与 CLEAR 时按 CLEAR 处理还是拒绝，应固定，建议拒绝歧义组合。若 PL/PS/DMA 在 RUNNING 或 DRAINING 中异常复位，本会话判为不可恢复的故障，原 `session_id` 不得继续产出正常帧；重新初始化资源、重新建立会话后才可恢复采集。设备重启后 `session_id` 可重用时，PC 必须按已有约定联合连接实例识别。

### 5. 样本、块与网络状态计数的对应关系

**现状及风险：** `daq_core.v:167-168` 直接读 64 bit `produced_samples` 的两半；现有“高低高”读取法适用于运行中稳定快照。数据源发出 `sample_valid` 后，BRAM 在下一拍写入，运行中计数可能短暂领先已写样本；PL 无“已 DMA 完成块数”寄存器。网络帧 `block_sequence`、`first_sample_index` 与状态中的 `uploaded_blocks`、`stored_blocks` 都需 PS 派生。

**建议定稿：** `produced_samples` 定义为本会话成功产生的样本数，而非 DMA 回收、TCP 发送或 SD 落盘数；运行中状态允许与这些计数异步，不作为确认块已可读的依据。PS 仅凭完成且长度/TLAST 正确的 DMA 块推进 `block_sequence`，从会话内完整块顺序计算 `first_sample_index`；首次为 0，每块加 4096，故障后不制造缺失块。停止或故障结算时说明各计数是否必须完全对齐、未消费完整块如何记录。状态 64 字节中所有计数是否随新会话归零也需明确。

## 建议一并写入协议的实现细节

1. `CONTROL` 仅低字节有效、CLEAR 是写入触发脉冲；写只读/非法地址及运行或待输出时 CLEAR 返回 AXI `SLVERR`。对 `RUN|CLEAR`、保留位、无效字节使能、非对齐访问规定结果，使 PS 驱动可测试。现有 RTL 对部分无效写入返回 OK 且不生效，定稿后需核对实现。
2. 区分 `STATUS.bit0` 采样运行、`bit1` PL 待输出、`bit2` 溢出锁存与网络 `state`。尤其 `bit1=0` 不能直接映射为网络 IDLE，仍可能有 DMA/PS/网络/SD 队列。
3. 固定 `TKEEP=0xFF`、每 4096 次有效握手 TLAST 一次、`TVALID && !TREADY` 时数据和边带保持稳定；PS 应把非完整 DMA 块视为故障。可将这组检查作为冻结后 PL 与 PS 的共同验收用例。
4. 如需在采集中查询状态，规定“高低高”重读超时与最大重试策略；采样计数可在读取过程增加，不能把单次 LO/HI 拼接值当作原子快照。

## v1.1 复核结论（2026/09/26）

对照协调者更新的 `Doc/控制协议/协议实现约定.md` v1.1 和 `Doc/项目管理/接口契约.md` v1.1，原第 1–5 项均已有可实施约定：

|原问题|v1.1 复核结果|
|---|---|
|RUN/START 门槛|START 仅在系统 IDLE 且资源排空时受理；DRAINING/FAULT 不预置 RUN；硬件 RUN=1 的合法条件、运行中幂等写入和启动确认顺序已明确。|
|停止和尾块|正常停止只输出完整块；PL、DMA、PS、TCP/SD 与资源释放的完成条件、故障完整前缀、异常通知和失败 STOP 应答顺序已明确。|
|溢出|未写入样本不计数；本会话锁存溢出由 PS 计为 0 或 1，进入 DRAINING 清理后以 FAULT 结束。|
|CLEAR/复位|CLEAR 仅在停采和 PL 排空后受理；RESET 的状态门槛、会话 ID 和计数语义、异常硬件复位处理已明确。|
|计数|`produced_samples`、`uploaded_blocks`、`stored_blocks`、`overflow_count`、队列值及运行中非原子快照的含义和正常停止计数等式已明确。|

**结论：** 未发现 v1.1 在 RUN/CLEAR、停止/异常或计数定义上的跨文档冲突，不再有阻断 PL 按协议实施的问题。v1.1 文首仍注明“审核通过并提交后”才成为共同基线；是否冻结及何时启动 PL 工作由协调者决定，本审查不代替该决定。

**冻结后的 PL 实现修正项：** 当前 `daq_core.v` 仍会对排空中或溢出后写 `RUN=1` 返回 OKAY，并可能产生延后启动；`RUN|CLEAR`、保留位写入也未按 v1.1 拒绝；读写地址忽略低两位，未对非对齐访问返回 SLVERR。后续 PL 实施需按 v1.1 修正并补对应仿真。建议协调者再补一句“违反 RUN=1 前置条件的写入返回 SLVERR 且不得改变控制状态”，以消除非法 RUN 的响应码歧义；这是接口文字精度建议，不影响确认当前实现违反受理条件。
