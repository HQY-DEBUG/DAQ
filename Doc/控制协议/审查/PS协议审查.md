## 已发现的协议待定项

1. **命令关联与帧边界**：约定称同时最多一个待应答命令，但又允许等待 STOP 时查询 STATUS。需明确 STOP 和 STATUS 可各有一个待应答、同 Type 禁止并发重试，超时后关闭连接重建会话；所有帧按完整外框串行发送，数据帧中途不得插入状态帧。未知 Type、过长 DataSize、坏包尾的应答或断链策略也需冻结。当前解析器对超长帧复位后重新搜索帧头，未知命令以 STATUS/BAD_REQUEST 回复。
2. **开始、停止与故障排空**：需定义 START 成功应答完整入 TCP 队列后才可出现首个数据帧；STOP 成功应答排在本会话最后完整数据帧之后，且所有需保存的数据已完成 SD 同步与关闭。TCP `tcp_write` 入队不代表 PC 收到或保存。故障中断时不能回正常 STOP 成功，必须定义终态、未完成尾块及最终计数。当前 `finish_stop` 以已入队块数判断，`app_fault` 进入 FAULT 后未统一完成资源排空/关闭。
3. **SD 故障策略**：应明确双输出遇 SD_FULL 时仅停 SD、发送一次异常事件并继续网络；只存储遇 SD_FULL 时停止采集、报告错误。双输出遇 SD_IO_ERROR 是否同样保留网络需由协调者裁决。`stored_blocks` 应明确是完整帧写入 FatFs 还是经 `f_sync` 持久化；短写、同步和关闭失败时不能把不完整帧计为成功。仅检查空闲簇为零可能漏判剩余空间不足一帧。
4. **状态与错误码**：建议命令应答的 `result` 表示本命令结果，STATUS/异常事件的 `result` 表示当前锁存故障；明确双输出 SD 满后 RUNNING、sd_state=FULL、状态查询可见 SD_FULL，以及随后 STOP 的结果与最终状态。定义 `queue_used` 是否包含正在发送的 DMA 槽和 lwIP 已复制的待发字节，防止将它误读为完整网络积压量。
5. **DMA 所有权与重启**：协议需要求旧会话所有 DMA BD、数据槽、网络发送和 SD 写入均释放后才允许新 START/CLEAR；FAULT 后复位流程应明确。当前 STOP 后未见 DMA 环停机，下一次 `daq_dma_start` 会清空软件状态并重建环，需在后续 PS 阶段验证和修正。
6. **64 位与文件边界**：72 小时需 259,200,000,000 个样本，所有产生、块序号、首样本索引和计数保持 64 bit；正常停止仅发完整 4096 样本帧，故障残块只在状态中计数。`.daq` 分卷上限为 1 GiB，切卷仅在完整帧之间；需确认实际 64 GB 卡文件系统、空间不足分类和 PC 保存失败后的接收校验行为。
